# NOAA 2012 revision of October 26, 2026

The catalogue now reads NOAA's 2012 Storm Events details file `c20261026`. NOAA replaced the `c20260323` file the catalogue cited before, and that address now returns 404. Compared with the published records, no tornado record was added or removed and one value changed: the begin time of `ncei:377993`. The CSV record number of all 1,058 records from 2012 moved, in a pattern that points to NOAA reordering the file. Every value in every other year is unchanged, including the time each file was first retrieved.

## How it was rebuilt

Every annual file from 1950 to 2025 was imported into an empty database with `python -m atlas import-ncei --year-range 1950 2025`, reusing downloads already cached on this computer. Since [pull request 195](https://github.com/T92T1914/tornado-atlas/pull/195), a file whose URL and SHA-256 match a retrieval the published catalogue already cites keeps that first retrieval time. All 75 unchanged files matched, so their records keep the times of September 20, 2026. Only the 2012 file has a new one. The browser catalogue was then exported from that database with `export_catalogue`. The Natural Earth map in `web/land.json` was not rebuilt.

The reported duration grows from 2 minutes to 15. NOAA gives no reason for the change in the file. The atlas shows the current value and does not choose between them.

## Row numbers

The record numbers moved by 905 different amounts, from 1 row to 45,959 rows. 545 records moved earlier in the file and 513 moved later. That looks like a reordering rather than an inserted block, though NOAA does not say what it changed. The browser sorts by year and record ID, so the order a visitor sees does not depend on the row. The record number in each record's provenance now points into the current file.

## What stays available

All 256 detail files are new. Records from 2012 sit in 251 of the 256 buckets, and their provenance changed. Every bucket also changed in byte form, because the exporter now writes the four casualty counts as whole numbers, `0` where the published files had `0.0`. `count()` in `atlas/ncei.py` has returned whole numbers since `75793d1` on September 21, 2026, the day after the published records were imported. Each export reads the records as its database stored them at import, so this is the first export from a database imported after that change. NOAA stores these counts as whole numbers, and every value is the same. A detail file is named by a hash of its bytes, so any republish from the current code would have made a new file in every bucket. The earlier detail files stay in `web/catalogue/details/`, because a detail file is named by its content hash and the exporter never deletes one. That keeps a page loaded before the change working, at the cost of about 175 MB more in the published site and about 18 MB compressed in the repository. The earlier index stays in the repository history.

## Limits

The comparison covered every value the browser catalogue publishes for each of the 80,318 records, which leaves out episode narratives. It compared values and not byte forms, which differ in every record as described above. It did not compare the two raw CSV files cell by cell, because the earlier 2012 file is no longer served and is not kept on the computer that made this record. A change in a raw cell the adapter does not carry into the catalogue, or in an episode narrative, would not show here. No location review cites a record from 2012, so none had to move.
